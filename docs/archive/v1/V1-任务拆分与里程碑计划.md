| V1-A 真实审美特征抽取 | 系统能否从真实图片 / 文本输入中抽取稳定、结构化、有 evidence 的审美特征 | accepted / archived |

## 4. V1 里程碑

### 4.1 Milestone 1：项目骨架与页面闭环

目标：

```text
前端能完成首页 → 上传页 → 分析等待页 → 报告页的基本路径。
```

归档结论：

- 页面骨架已完成。
- 页面表达已约束为审美观察，不输出心理测试、玄学或人格诊断。
- 页面字段和报告结构已对齐 `../../06-输出报告模板文档.md`。

### 4.2 Milestone 2：后端 API Skeleton

目标：

```text
后端暴露 V1 必要 API，并保持 route / service / repository 分层。
```

归档结论：

- `GET /api/health`、`POST /api/inputs`、`POST /api/analysis-jobs`、`GET /api/analysis-jobs/{job_id}`、`GET /api/reports/{report_id}`、`POST /api/insights/{insight_id}/feedback` 已完成。
- API request / response 使用 Pydantic schema。
- HTTP 层、业务逻辑和数据访问已分层。

### 4.3 Milestone 3：数据结构与存储闭环

目标：

```text
V1 的业务事实可以保存，向量 metadata 和业务数据边界清楚。
```

归档结论：

- PostgreSQL 或当前 repository mock 是业务事实来源。
- ChromaDB 只保存向量和检索 metadata，不作为业务数据库。
- `analysis_logs` 已记录基础执行日志。

### 4.4 Milestone 4：Mock AI Workflow

目标：

```text
先用 mock AI client 跑通 V1 分析链路，保证 schema 稳定。
```

归档结论：

- mock 输出和真实模型预期输出使用同一 schema。
- 每条洞察至少有一个 evidence ref。
- 相似性分组不被表达成绝对聚类结论。

### 4.5 Milestone 5：前后端联调

目标：

```text
前端通过真实 API 获取任务状态、报告和反馈结果。
```

归档结论：

- 用户可以从上传走到报告。
- 反馈可以提交并得到明确结果。
- 前端类型与后端 schema 对齐。

### 4.6 Milestone 6：V1 验收与归档

目标：

```text
按 V1 收口清单完成验收，并把实际状态写入执行记录和 archive。
```

归档结论：

- V1 已按 `V1-验收核对表.md` 完成验收。
- V1 遗留问题已进入 `V1-遗留问题.md`。
- V1 已归档为 stable baseline。

## 5. V1 AI 生成代码顺序

V1 开发期采用的推荐顺序：

1. Pydantic schema 和 TypeScript type 对齐。
2. Repository 或当前 in-memory store。
3. Service。
4. Workflow step。
5. API route。
6. 前端 service。
7. 前端页面或 feature component。
8. 单元测试或集成测试。
9. 文档状态更新。
