# AI 审美形成系统：V1 遗留问题

## 1. 文档职责

这份文档只记录 V1 验收后的遗留问题。

遗留问题分三类：

- 必须在 V1 归档前解决。
- 可以进入 V2 前解决。
- 明确延后到 V2 / V3 / V4。

## 2. 必须在 V1 归档前解决

当前必须解决或确认：

- 浏览器中手动跑通完整路径：上传样本 → 分析等待 → 报告 → 反馈。
- 确认前端页面是否已经完全接入真实 API，而不是部分使用 mock data。
- 补齐或明确放宽 `analysis_logs`：当前 workflow 没有持久记录 step、状态、模型、耗时和错误。
- 确认 `insights` 是否必须独立持久化；当前验收中已确认报告结构包含 insights，但不是独立表级持久化。
- 确认 ChromaDB runtime 写入是否是 V1 必须项；当前是 mock embedding metadata / 抽象替代。
- 处理或记录 Pydantic / FastAPI alias warning：当前测试通过，但 pytest 有 3 条 `UnsupportedFieldAttributeWarning`。

## 3. 可以进入 V2 前解决

可能包括：

- PostgreSQL 从 in-memory repository 替换为真实 runtime 连接。
- ChromaDB 从抽象占位替换为真实 runtime 连接。
- 前端错误态和空状态打磨。
- 图片真实文件存储与真实图片内容读取。
- 将当前本地启发式文本抽取替换为真实 LLM prompt runtime。

这些问题是否能延后，取决于 V1 验收时系统是否已经能演示完整闭环。

## 4. V1-A 已收口内容

2026-06-16 已完成：

- 新增 `FeatureExtractor` 抽象，workflow 可注入不同 extractor。
- 默认保留 `MockFeatureExtractor`，现有 mock workflow 和 API 路径不变。
- 新增本地 `HeuristicFeatureExtractor`，用于文本特征抽取边界。
- `InputFeature` schema 新增 `modelName`，并要求 feature evidence 非空。
- 新增 `validate_input_feature`，阻止缺少 `promptVersion`、`modelName` 或 evidence 的 feature 进入 workflow。
- 图片输入当前明确为 placeholder feature：真实图片分析依赖后续文件存储接入。

## 5. 明确延后到 V2

- 历史报告列表。
- 报告详情回看。
- 最近两次报告对比。
- 轻量用户画像。
- 反馈影响画像权重。

## 6. 明确延后到 V3

- personalized retrieval。
- 审美知识库 RAG。
- evidence coverage。
- feedback hit rate。
- grouping stability。
- prompt versioning dashboard 或日志查询。

## 7. 明确延后到 V4

- 音乐输入。
- 视频输入。
- 外部收藏源导入。
- 审美时间轴。
- 审美知识图谱。
- 审美观察 Agent。
- MCP 外部上下文接入。
