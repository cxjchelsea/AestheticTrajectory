```text
在 V2 Memory / User Model baseline 之上，引入 personalized history retrieval、审美知识 RAG、evaluation metrics 与 retrieval / RAG observability，且不破坏 evidence-first 与 non-diagnostic 表达规则。
```

```text
报告生成时的历史参考、知识解释支持、开发期质量指标与可观测 trace；不把检索结果写成用户偏好证据。
```

## 5. V3 里程碑

### 5.1 Milestone 1：版本级研究与边界确认

目标：

```text
明确 V3 personalized retrieval、RAG、evaluation、observability 的能力地图、边界与子阶段依赖，不破坏 V2 evidence-first 规则。
```

完成结果：

- 完成 V3-0 版本级研究（含 OpenTelemetry / LLM observability / RAG evaluation 调研）。
- 确认子阶段顺序：V3-A → V3-B → V3-C → V3-D → V3-E。
- 明确不提前进入 V4 Agent / MCP / ChromaDB runtime。
- 用户确认 V3 子阶段拆分与设计取舍。

### 5.2 Milestone 2：Personalized history retrieval（V3-A）

目标：

```text
报告生成可参考同用户历史报告与反馈，并在报告详情可追溯展示，且与当前输入 evidence 分离。
```

完成结果：

- 新增 `retrieve_personal_history` workflow step。
- 新增 `PersonalHistoryContext` / `HistoryContextItem` schema。
- 新增 `build_personal_history_context`（overlap gate、recency tie-break、`not_me` negative）。
- 报告详情「历史参考」UI。
- 单元测试 `test_personal_history_retrieval.py`。
- 人工验收通过。

### 5.3 Milestone 3：Aesthetic knowledge RAG（V3-B）

目标：

```text
引入静态审美知识库检索，为解释提供 knowledge context，且不进入 profile positive evidence。
```

完成结果：

- 新增 `retrieve_aesthetic_knowledge` workflow step。
- 新增 `AestheticKnowledgeContext` / `KnowledgeContextItem` schema。
- 新增静态知识库 `AESTHETIC_KNOWLEDGE_CHUNKS`。
- `MIN_FEATURE_OVERLAP`、overlap ranking、out-of-scope abstention。
- 报告详情「知识参考」UI。
- 单元测试 `test_aesthetic_knowledge_retrieval.py`。
- 人工验收通过。

### 5.4 Milestone 4：Evaluation metrics baseline（V3-C）

目标：

```text
为 mock / heuristic pipeline 建立 deterministic evaluation baseline，并支持 feedback 后刷新。
```

完成结果：

- 新增 `compute_report_evaluation` workflow step。
- 新增 `GET /api/reports/{report_id}/evaluation`。
- 指标：evidenceCoverage、retrievalCoverage、unsupportedInsightCount、feedbackHitRate、schemaPassRate。
- `evaluationMetrics` 写入 `report_json`。
- 前端「质量评估」分区与 feedback 后自动刷新。
- 单元测试 `test_report_evaluation.py`。
- 人工验收通过（含 not_me → feedbackHitRate 0% 确认）。

### 5.5 Milestone 5：Retrieval / RAG observability（V3-D）

目标：

```text
补全 retrieval / context / evaluation trace，并提供开发者可查看的 debug 入口。
```

完成结果：

- 新增 `observability_trace.build_debug_traces`。
- 扩展 `AnalysisJobDebugResponse` 与 `GET /api/analysis-jobs/{job_id}/debug`。
- Developer Debug Panel 四个 trace 分区（dev-only）。
- 单元测试 `test_observability_trace.py`。
- 人工验收通过。

### 5.6 Milestone 6：Stability and governance validation（V3-E）

目标：

```text
验收 V3 不把 RAG 知识当成用户偏好证据，不让历史检索覆盖当前输入证据，不生成无 evidence 的高级结论。
```

完成结果：

- 新增 `test_v3_governance_validation.py`（6 项自动治理检查）。
- 补强 `test_analysis_workflow.py` V3 断言。
- 人工全链路验收通过（§6.1 清单）。

## 6. V3 明确不做

V3 不实现：

- ChromaDB runtime 写入和查询。
- 真实 LLM / vision / embedding runtime。
- 外部审美知识库 RAG runtime（非静态 KB）。
- LangSmith / OpenTelemetry / 外部 observability SaaS。
- grouping stability、failure replay 完整评估 runtime。
- 复杂 evaluation dashboard / LLM-as-judge。
- Agent / MCP / 知识图谱。
- 音乐 / 视频 / 外部收藏源。
- 把 retrieval context 写入 profile positive evidence。
- 把 history / knowledge refs 混入 insight `evidenceRefs`。
