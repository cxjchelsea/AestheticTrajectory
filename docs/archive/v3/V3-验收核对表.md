## 3. API

### 3.0 V2 基线 API（V3 归档时仍有效）

- [x] `GET /api/health` 可用。
- [x] `POST /api/inputs` 可创建输入。
- [x] `POST /api/analysis-jobs` 可创建并完成分析任务。
- [x] `GET /api/reports/{report_id}` 可查询报告详情。
- [x] `GET /api/users/{user_id}/reports` 可查询历史报告列表。
- [x] `GET /api/users/{user_id}/profile` 可查询轻量画像。
- [x] `GET /api/users/{user_id}/reports/comparison/latest` 可查询最近两次报告对比。
- [x] `GET /api/insights/{insight_id}/feedback` 可读取当前 feedback。
- [x] `POST /api/insights/{insight_id}/feedback` 可提交或修改 feedback。
- [x] 不存在 insight 提交 feedback 时返回 404。

### 3.1 V3 新增 / 扩展 API

- [x] `GET /api/reports/{report_id}/evaluation` 存在报告时返回 `ReportEvaluationResponse`。
- [x] evaluation 响应包含 `reportId`、`metrics`、`summary`、`disclaimer`。
- [x] `metrics` 包含 `evidenceCoverage`、`retrievalCoverage`、`unsupportedInsightCount`。
- [x] `metrics` 包含 `feedbackHitRate`（无 feedback 时为 `null`）。
- [x] `metrics` 包含 `schemaPassRate`（无 applicable schema record 时为 `null`）。
- [x] `metrics` 包含 `insightCount`、`historyContextItemCount`、`knowledgeContextItemCount`。
- [x] 提交 feedback 后再次请求 evaluation，metrics 反映最新 feedback。
- [x] `GET /api/analysis-jobs/{job_id}/debug` 返回 `retrievalTrace`（长度 2）。
- [x] debug 响应包含 `retrievalItems`、`contextAssemblyTrace`、`evaluationTrace`。
- [x] `retrievalTrace` 项包含 `stepId`、`retrievalType`、`status`、`selectedItemCount`、`abstained`、`message`。
- [x] `retrievalItems` 项包含 `retrievalType`、`itemId`、`label`、`matchedFeatures`、`sourceRefs`。
- [x] `evaluationTrace.metrics` 与 report `evaluationMetrics` 一致。

### 3.2 扩展后的报告详情 API

- [x] `GET /api/reports/{report_id}` 返回 `historyContext`（可为 abstain message 或 items）。
- [x] `GET /api/reports/{report_id}` 返回 `knowledgeContext`（可为 abstain message 或 items）。
- [x] `GET /api/reports/{report_id}` 返回 `evaluationMetrics`（workflow 写入 `report_json`）。
- [x] `historyContext.items` 每条包含 `sourceType`、`sourceId`、`sourceRefs`、`direction`、`matchedFeatures`。
- [x] `knowledgeContext.items` 每条包含 `docId`、`title`、`snippet`、`matchedFeatures`、`sourceRefs`。
- [x] insight `evidenceRefs` 仍只引用当前 report 的 input ids，不包含 history / knowledge docId。

### 3.3 收口观察项

- [x] debug API 保持 dev 能力语义，不暗示生产监控平台已接入。
- [x] 不新增 V3 专用外部 observability SaaS endpoint。

## 5. Workflow / 服务边界

### 5.0 V2 基线 workflow（V3 归档时仍有效）

- [x] API route 只处理 HTTP 层；业务逻辑进入 service；数据访问进入 repository。
- [x] workflow 能从创建分析任务执行到保存报告。
- [x] workflow 生成的 report id 可用于后续查询；insight id 可用于后续 feedback。
- [x] profile builder 从 reports + feedback 构建画像，不凭空生成无 evidence 的画像项。
- [x] report comparison service 从最近两份 report_json 生成只读对比结果。
- [x] feedback 更新后重新查询 profile，画像可反映当前 feedback。
- [x] 本地 mock / fallback 报告不会写入真实 feedback 或 profile evidence。
- [x] V2-E profile evidence coverage、被否定解释复现和 feedback influence 定向检查仍有效。

### 5.1 V3 workflow 顺序

- [x] `extract_features` → `generate_embeddings` → `write_vectors` → `cluster_inputs`。
- [x] `retrieve_personal_history` 在 `generate_report` 之前执行。
- [x] `retrieve_aesthetic_knowledge` 在 `generate_report` 之前执行。
- [x] `generate_report` 接收 `historyContext` 与 `knowledgeContext`。
- [x] `compute_report_evaluation` 在 `save_report` 之前执行。
- [x] evaluation metrics 写入 report 后再 `save_report`。

### 5.2 V3-A history retrieval 服务

- [x] `build_personal_history_context` 限定同用户历史 reports / feedback。
- [x] 无特征重叠时 history feedback 不进入 context。
- [x] 按 overlap-count 排序，recency tie-break。
- [x] `not_me` 只作为 negative context，不作为正向偏好。
- [x] 无相关历史时返回明确 message，不伪造 items。

### 5.3 V3-B knowledge retrieval 服务

- [x] `build_aesthetic_knowledge_context` 使用静态知识库 `AESTHETIC_KNOWLEDGE_CHUNKS`。
- [x] `MIN_FEATURE_OVERLAP = 1`，低于阈值 abstain。
- [x] overlap 降序，docId tie-break。
- [x] 每条 item 必须有 `sourceRefs` 与 `matchedFeatures`。
- [x] 知识只作 explanation support，不进入 profile positive evidence。

### 5.4 V3-C evaluation 服务

- [x] `evidenceCoverage` 要求 insight evidenceRef 绑定当前 input id。
- [x] `retrievalCoverage` 统计 history + knowledge items 的 sourceRefs 覆盖率。
- [x] `unsupportedInsightCount` 统计无当前 input evidence 的 insight。
- [x] `feedbackHitRate` 只统计 `somewhat_me` / `very_me`。
- [x] `schemaPassRate` 只统计 passed/failed schema records，忽略 not_recorded。

### 5.5 V3-D observability 服务

- [x] `build_debug_traces` 从 persisted report + workflow logs 组装 trace。
- [x] history abstain 时 `retrievalTrace.abstained = true` 且保留 message。
- [x] 不接入 LangSmith / OpenTelemetry runtime。

### 5.6 V3-E governance 测试

- [x] `test_v3_governance_validation.py` 覆盖 insight evidence 隔离。
- [x] 覆盖第二份报告 history 与 insight evidence 分离。
- [x] 覆盖 knowledge / history 不进 profile positive evidence。
- [x] 覆盖 workflow unsupportedInsightCount = 0。
- [x] `test_analysis_workflow.py` 补强 V3 context / evidence 断言。

### 5.7 收口观察边界

- [x] ChromaDB 仍不作为 V3 业务检索来源。
- [x] MockFeatureExtractor / MockEmbeddingClient / mock workflow 边界保持可见。
- [x] 不把 V3 retrieval context 写成当前输入 primary evidence。

## 6. 边界与表达

### 6.1 已确认边界

- [x] 不包含 ChromaDB runtime 写入和查询。
- [x] 不包含真实 LLM / vision / embedding runtime。
- [x] 不包含外部审美知识库 RAG runtime（非静态 KB）。
- [x] 不包含 LangSmith / OpenTelemetry / 外部 observability SaaS。
- [x] 不包含 grouping stability、failure replay 完整 runtime。
- [x] 不包含 Agent / MCP / 知识图谱。
- [x] 不把 RAG 知识当成用户偏好证据写入 profile。
- [x] 不让历史检索覆盖当前输入 evidence。
- [x] 不生成无 evidence 的高级结论（workflow 正常路径 unsupported = 0）。

### 6.2 收口观察边界

- [x] history / knowledge disclaimer 可否定诊断，但 message / note 不做断定式人格 / 心理 / 能力判断。
- [x] evaluation summary 不输出诊断式表达。
- [x] feedbackHitRate = 0% 在 `not_me` 时为设计预期，不是 bug。
