# AI 审美形成系统：文档体系说明

## 1. 文档排序原则

当前 `docs/` 目录按“从想清楚到做出来”的顺序编号：

```text
00 入口导航
01 产品定义
02 版本路线
03 MVP 范围
04-06 AI 认知与输出
07-11 工程设计
12 开发执行
13-14 验证与展示
15 迭代记录
16 开发收口
archive 历史版本归档
```

这个顺序不是按文档创建时间排，而是按项目推进顺序排：

```text
先明确项目是什么
↓
再明确分几版做
↓
再锁定第一版范围
↓
再定义 AI 怎么理解和输出
↓
再定义系统怎么落地
↓
最后定义怎么验证、展示和开发收口
```

## 4. 文档分层

### 4.1 项目级规划：01-03

这组只负责“做什么”和“为什么做”。

- `01` 定义项目灵魂。
- `02` 定义多版本路线，只回答每个版本为什么存在。
- `03` 锁定第一版 MVP 的产品范围和用户体验边界。

规则：

- 不在产品组里写具体代码目录。
- 不在 MVP 文档里塞 V2 / V3 / V4 的工程任务。
- 如果版本边界冲突，以 `02-版本迭代路线图.md` 为准。
- 如果 MVP 功能冲突，以 `03-MVP功能需求文档.md` 为准。

### 4.2 AI 设计：04-06

这组只负责“AI 如何理解、分析、表达”。

- `04` 定义底层表征，不讨论后端架构。
- `05` 定义分析逻辑，不讨论页面布局。
- `06` 定义报告输出，不新增系统功能。

规则：

- 底层特征字段只在 `04` 里做权威定义。
- 分析流程以 `05` 为准。
- 报告语气和禁止表达以 `06` 为准。

### 4.3 工程设计：07-11

这组只负责系统设计和模块契约。

- `07` 是系统架构和数据结构。
- `08` 是代码目录和分层。
- `09` 是 workflow 执行顺序。
- `10` 是 prompt contract。
- `11` 是模块拆分和接口测试。

规则：

- 数据库和 API 以 `07` 为准。
- 代码放置以 `08` 为准。
- 分析任务步骤以 `09` 为准。
- LLM 输出 schema 以 `10` 为准。
- 模块验收以 `11` 为准。

### 4.4 开发执行与状态：12、15、16

这组只负责“怎么推进、做到哪了、如何收口”。

- `12` 是当前版本的开发任务拆分，不重新定义版本路线。
- `15` 是每轮迭代的实际执行记录，记录完成情况、测试、复盘和遗留问题。
- `16` 是 V1 的验收清单，只用于判断 V1 是否完成。

规则：

- 版本目标以 `02` 为准，`12` 不重复定义长期路线。
- MVP 产品范围以 `03` 为准，`16` 不重复解释产品愿景。
- V1 是否完成以 `16` 的清单为准。
- 实际完成情况以 `15` 和 `archive/` 为准。

### 4.5 验证与展示：13-14

这组只负责“怎么证明、怎么讲”。

- `13` 定义验证方法。
- `14` 定义项目展示和简历包装。

规则：

- `14` 不能反向决定 MVP 范围。
- `13` 可以约束报告质量和测试标准。

### 4.6 历史归档：archive

归档只保存版本事实，不保存仍在维护的设计规范。

- 仍会指导后续版本的文档继续留在 `docs/`。
- 已完成版本的完成清单、测试记录、遗留问题和复盘进入 `archive/`。
- 归档文档不能反向修改当前版本范围。

## 8. 新增文档规则

以后新增文档前，先判断是否能放进现有文档。

只有出现以下情况才新增：

- 已有文档会变得过长。
- 新内容属于新的职责边界。
- 新内容会被频繁单独引用。

新增编号建议：

- 产品路线类放在 `02` 附近。
- MVP 需求类放在 `03` 附近。
- AI 分析类放在 `04-06`。
- 工程实现类放在 `07-12`。
- 验证展示类放在 `13-14`。
- 迭代执行记录使用 `15`。
- 版本收口清单使用 `16` 或后续版本编号。
- 已完成版本事实放入 `archive/<version>/`。
协作规范不进入项目设计编号体系；例如 Git 提交规范使用英文文件名 `git-commit-message-guide.md`。

## 9. 当前阶段提醒

当前只应该专注 V0 / V1：

- V0：前端原型 + mock 报告。
- V1：真实输入、底层特征、embedding、相似性分组、报告、反馈。

暂时不要提前实现：

- RAG
- Agent
- MCP
- 知识图谱
- 音乐 / 视频
- 复杂长期画像

一句话：

> 文件编号就是项目推进顺序；文档定位就是每份文档只回答一个层级的问题。
