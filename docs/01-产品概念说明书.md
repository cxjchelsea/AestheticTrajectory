# AI 审美形成系统：产品概念说明书

## 1. 项目一句话定义

AI 审美形成系统是一个以审美为切口的长期个性化 AI 系统。它不只是判断用户喜欢什么，而是观察、解释和记录用户的审美如何被输入影响、如何逐渐形成、如何随时间发生变化。

更简洁的产品表达是：

> 一个追踪个人审美演化的 AI。

更技术化的项目表达是：

> 基于多模态 embedding、长期记忆与可解释分析的个人风格演化建模系统。

面向招聘和工程展示时，可以进一步表达为：

> 一个面向长期个性化 AI 的多模态用户偏好建模系统，通过结构化特征提取、embedding 相似性分组、个性化历史检索、RAG 审美知识增强、LLM 可解释生成与用户反馈闭环，持续建模用户审美偏好的形成与变化。

## 2. 项目在长期体系中的位置

本项目不是一个孤立的审美分析工具，而是长期个人 AI 系统“墨核”的第一个 MVP 场景。

选择审美作为切口，是因为审美天然适合验证长期个性化 AI 的关键问题：

1. 输入是多模态的：图片、文字、风格、语境和反馈会共同影响用户偏好。
2. 偏好是长期变化的：用户不是固定喜欢某一种风格，而是会随着输入、经历、创作和生活阶段变化。
3. 解释比推荐更重要：系统不只是告诉用户“你喜欢什么”，而是解释“你为什么可能被这些东西吸引”。
4. 反馈很有价值：用户对洞察的认可或否定，可以逐渐形成更准确的个人偏好模型。
5. 它适合验证长期个性化 Agent 的核心问题：AI 如何长期理解一个人的偏好形成过程。

因此，本项目的长期意义不是“做一个审美报告工具”，而是为墨核验证一套可迁移的长期个性化能力：

```text
多模态输入
↓
结构化表征
↓
可解释分析
↓
用户反馈
↓
长期记忆
↓
偏好演化
↓
个性化 Agent
```

## 3. 对应的 Agent 前沿方向

本项目长期对应以下 Agent 前沿方向，但不会在 V1 一次性全部实现。

### 3.1 Memory / User Model

Memory System 是墨核的核心，也是这个项目最有长期壁垒的一层。

在审美系统中，记忆不是简单保存聊天记录，而是要把用户的多模态输入、反馈、被认可的解释、被否定的解释、稳定偏好和近期变化组织成可解释、可修正的长期偏好结构。

它包含：

```text
短期记忆
长期记忆
偏好记忆
情境记忆
事件记忆
用户画像
记忆写入
记忆更新
记忆遗忘
记忆冲突解决
记忆可解释
记忆治理
多模态记忆
```

关键问题不是“能不能存”，而是：

```text
什么应该记？
什么不该记？
什么时候更新？
什么时候遗忘？
新证据和旧记忆冲突怎么办？
用户能否查看、编辑、删除？
记忆会不会让 Agent 固化偏见？
```

墨核是这一层的主项目；审美系统是长期偏好记忆的第一个应用场景。V1 只保存输入、特征、报告和反馈，不直接生成长期画像；V2 开始把反馈和历史报告转化为轻量用户模型；后续版本再处理更复杂的记忆更新、遗忘、冲突和治理问题。

### 3.2 Multimodal Preference Modeling

审美偏好不是纯文本偏好，而是由图片、文字、颜色、材质、构图、情绪、风格和反馈共同组成。

系统需要把这些输入转化为可比较、可保存、可解释的结构化表示。

### 3.3 Temporal User Profiling

系统最终要区分：

```text
长期稳定偏好
阶段性偏好
近期新出现的偏好
正在减弱的偏好
被用户明确否定的解释
被用户多次认可的解释
```

这意味着项目不能只做一次性报告，而要逐渐进入时间型用户画像。

### 3.4 Preference Explanation

本项目不以“推荐更多内容”为第一目标，而是以“解释偏好”为核心目标。

系统应该回答：

```text
你不是简单喜欢这张图；
你可能被它的低饱和、人物缺席、空间密度低和冷静结构吸引。
```

因此，解释必须来自输入证据，而不能是空泛的人格判断。

### 3.5 Skill / Capability

后续版本中，系统可以沉淀出多个可复用能力。这里的 Skill 不是普通工具，也不是完整项目，而是把一类任务中可复用的步骤、模板、评估标准和失败处理方式封装成能力包。

```text
图片审美分析能力
文本审美分析能力
风格归因能力
审美变化报告能力
用户反馈总结能力
偏好画像更新能力
```

这些能力后续可以被墨核、服装认知系统、内容创作系统等复用。

V1 不直接建设 Skill Library，但 V1 的 workflow step、prompt contract、schema validator 和测试用例应该为后续 Skill 沉淀保留边界。

### 3.6 Evaluation / Observability

Evaluation 不是附加功能，而是 Agent 从 Demo 走向系统的核心能力。系统需要评估：

```text
特征提取是否稳定
输出 schema 是否通过
洞察是否有证据
用户是否认可洞察
同类输入是否产生一致解释
不同 prompt 版本效果是否变化
```

同时需要记录 prompt version、model name、latency、error type、evidence trace 等信息。

这些评估和观测能力会横切后续版本：V1 先保证 schema、evidence 和基础日志；V3 再扩展为更系统的 evidence coverage、feedback hit rate、grouping stability 和失败回放。

### 3.7 Governance

治理与安全不是后期附加功能，而是所有版本都必须内置的安全边界。审美系统尤其必须避免：

```text
把单一审美标准强加给用户
把审美偏好解释成人格诊断
制造身体羞辱或审美规训
使用玄学化、命运化、心理测试式表达
把模型解释当作事实
未经用户确认就固化长期偏好
```

治理不是后期附加功能，而是从 V1 起就应该体现在输出边界和反馈机制中。

对本项目来说，Governance 首先体现在：

- 不把模型解释包装成事实。
- 不把审美偏好解释成人格诊断。
- 不未经用户确认就固化长期偏好。
- 不用推荐、消费或规训逻辑覆盖用户的自我理解。
- 允许用户通过反馈修正系统解释。

## 4. 核心问题

普通推荐系统关注的是：

- 用户现在喜欢什么
- 下一步应该推荐什么
- 如何提高点击率、收藏率、转化率

这个系统关注的是：

- 用户为什么会喜欢这些东西
- 用户的审美偏好是如何形成的
- 某种风格如何在长期输入中逐渐出现
- 不同输入之间是否存在隐含关联
- 审美如何反过来影响用户表达
- 用户的风格画像如何随时间演化

因此它不是一个推荐工具，而是一个审美观察系统。

## 5. 产品核心视角

这个项目最大的优势在于：

> “AI 审美形成系统”不是一个功能，而是一个视角。

它真正有意思的地方不是 AI 能给用户贴标签，而是 AI 能像观察者一样告诉用户：

> “我注意到你正在发生这样的变化。”

系统不应该只回答：

> “你喜欢什么？”

而应该进一步回答：

> “你为什么慢慢开始喜欢这些东西？”

这会让产品从工具进入成长维度。

## 6. 产品定位

### 6.1 它是什么

它是一个 AI 审美镜子。

用户上传自己最近喜欢的图片、文字、音乐、收藏内容或其他审美样本，系统会先提取这些输入中的底层审美特征，再基于聚类关系和历史反馈生成多个可能解释，并输出有依据的审美洞察。

随着输入积累，系统会进一步形成用户的审美轨迹，观察用户偏好如何迁移、哪些主题持续出现、哪些风格正在增强或消退。

### 6.2 它不是什么

它不是：

- AI 收藏夹
- 普通推荐系统
- Pinterest + GPT
- Notion 式资料管理工具
- Obsidian 式知识库工具
- AI 心理测试
- AI 算命
- AI 灵魂分析

这些方向会削弱项目的独特性，让它看起来像套壳工具或娱乐测试。

## 7. 目标用户

### 7.1 第一阶段目标用户

第一阶段更适合面向对审美、表达和自我观察有兴趣的人：

- 设计学习者
- 服装 / 视觉 / 产品设计爱好者
- 内容创作者
- 摄影、绘画、写作爱好者
- 喜欢收藏图片、文字、音乐的人
- 希望理解自己风格偏好的人
- 对 AI 个性化系统感兴趣的人

### 7.2 不是第一阶段目标用户

第一阶段不优先服务：

- 只想获得穿搭推荐的人
- 只想找图片素材的人
- 只想快速生成内容的人
- 只关注效率工具的人
- 期待系统给出绝对答案的人

这个系统的第一批用户应该能接受“解释型产品”的体验，而不是只追求直接产出。

## 8. 核心使用场景

### 8.1 瞬时审美剖析

用户上传一组最近喜欢的内容，系统立即输出：

- 底层特征摘要
- 风格倾向
- 情绪倾向
- 可能解释
- 风格矛盾
- 隐含偏好
- 可解释依据

这是第一天就能产生价值的核心场景。

### 8.2 审美轨迹观察

用户持续记录喜欢的内容，系统逐渐形成：

- 审美时间轴
- 偏好迁移记录
- 风格变化趋势
- 长期主题复现
- 近期变化提醒

这是长期价值场景。

### 8.3 创作前的自我理解

用户在做设计、写作、穿搭或创作前，可以通过系统理解自己近期的审美状态：

- 最近在被什么风格吸引
- 哪些意象反复出现
- 当前表达更偏叙事性还是结构性
- 是否正在从某种风格转向另一种风格

### 8.4 简历 / 作品集展示

作为个人 AI 项目，它可以展示：

- 多模态处理
- embedding 建模
- 长期记忆
- 用户建模
- 可解释 AI
- AI 产品思维
- 差异化系统设计能力

## 9. 产品价值

### 9.1 对用户的价值

用户获得的不是普通推荐，而是：

- 被理解的感觉
- 对自己审美偏好的命名
- 对隐含风格倾向的发现
- 对长期变化的观察
- 对创作方向的启发

它最重要的体验不是“准确率 99%”，而是：

> 用户觉得：这真的很像我。

### 9.2 对开发者的价值

这个项目能体现开发者不是只会调 API，而是在思考：

- AI 如何理解用户
- 长期个性化如何设计
- 审美这种非客观对象如何建模
- LLM 输出如何有依据
- 产品如何避免玩具化

这会让项目具有作品感和辨识度。

## 10. 产品气质

这个系统不应该像心理测试网站，也不应该像神秘主义工具。

它应该像一个实验性 AI Lab 产品：

- 克制
- 理性
- 有研究感
- 有美学
- 有解释依据
- 有长期观察感

气质可以参考：

- Are.na
- Cosmos
- Obsidian Research
- Apple ML Demo
- Anthropic Research Prototype

界面表达应避免：

- 紫色星空
- 玄学语录
- 神秘占卜感
- “你的灵魂动物是……”这类表达
- 泛泛的人格判断

## 11. 产品原则

### 11.1 不做空泛判断

避免输出：

> 你是一个敏感又孤独的人。

应该输出：

> 你的输入中反复出现低饱和色、空旷空间和工业材质，因此系统推测你对“结构化孤独感”有稳定偏好。

### 11.2 不把成长放在第一层

用户第一天就要得到反馈。长期成长应该是隐藏主线，而不是强迫用户打卡半年后才出现价值。

第一层是：

> AI 好懂我。

第二层是：

> AI 发现了我自己没发现的东西。

第三层才是：

> 原来我的审美一直在变化。

### 11.3 解释比结论更重要

审美不是客观题。系统不需要证明自己绝对正确，而要证明自己的解释有依据。

### 11.4 先做有趣，再做严谨

第一版不追求学术级验证，而是先做出一个能让用户惊讶的小系统：

> “它为什么这么懂我？”

之后再逐步加入一致性验证、长期记忆、演化分析和更严谨的评估机制。

## 12. 第一阶段产品目标

第一阶段目标不是做完整平台，而是做一个最小但有灵魂的核心体验：

> 用户上传一组审美样本，系统即时生成一份有解释依据的审美剖析报告。

第一阶段必须做到：

- 用户 5 分钟内理解产品
- 用户第一次使用就获得有趣洞察
- 输出不能像算命
- 每个洞察都要有输入依据
- 可以收集用户反馈
- 可以为后续长期轨迹积累数据

## 13. 长期愿景

长期来看，这个系统可以发展为：

> 多模态长期风格建模系统。

它通过图片、文字、音乐、视频等输入持续建模用户的审美空间，记录偏好如何迁移，解释风格如何形成，并在用户创作、消费、穿搭、设计和表达中提供个性化理解。

它不是推荐用户喜欢的东西，而是帮助用户理解：

> 自己为什么会成为现在这个审美上的自己。

## 14. 工程表达边界

这个项目需要同时具备产品表达和工程表达。

产品表达强调：

- 审美镜子
- 审美轨迹
- 被观察的成长感
- 个人风格演化

工程表达强调：

- 多模态输入管线
- 结构化 feature pipeline
- embedding 审美空间
- personalized memory retrieval
- RAG 审美知识增强
- Function Calling 工具编排
- explainable insight generation
- evaluation 与 observability
- long-term user profile

但这些技术不应该被一次性堆进 MVP。第一阶段应先证明“结构化分析 + 可解释报告 + 用户反馈”成立；进阶阶段再引入 Function Calling、RAG、可观测性和长期画像；高级阶段再扩展审美观察 Agent、审美知识图谱和 MCP 外部上下文接入。
