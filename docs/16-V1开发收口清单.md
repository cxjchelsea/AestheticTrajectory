## 1. 文档目的

这份文档用于收口 V1 的工程验收范围。

它不定义新的产品愿景，也不重新解释 MVP 产品范围，只把 V1 必须验收的工程内容压成一张清单：

- V1 要建哪些表。
- V1 要提供哪些 API。
- V1 要做哪些前端页面。
- V1 mock AI 输出 schema 是什么。
- V1 完成标准是什么。

职责边界：

- MVP 做什么、不做什么，以 `03-MVP功能需求文档.md` 为准。
- V1 的具体工程验收，以本文档为准。
- V1 实际完成情况、测试结果、遗留问题，以 `15-迭代执行记录.md` 和 `archive/v1/` 为准。
- 如果其他文档里出现 V2 / V3 能力，本文档优先用于判断 V1 是否需要实现。

## 2. V1 一句话目标

> 用户上传 3-10 个图片 / 文本样本，系统保存输入，提取底层特征，生成 embedding，做小样本相似性分组，生成有证据绑定的审美报告，并保存用户反馈。

## 3. V1 明确不做

V1 不做：

- 完整登录系统
- 历史报告列表
- 报告对比
- 长期用户画像
- RAG
- Agent
- MCP
- 知识图谱
- 音乐 / 视频输入
- 外部平台导入
- 自动推荐

这些能力从 V2 或更后版本开始。

## 4. V1 前端页面

### 4.1 首页

必须包含：

- 产品一句话说明
- 上传入口
- 示例洞察

### 4.2 上传页

必须包含：

- 图片上传
- 文字输入
- 样本预览
- 删除样本
- 样本数量提示
- 开始分析按钮

限制：

- 最少 3 个样本。
- 建议 5-10 个样本。
- 最多 12 个样本。

### 4.3 分析等待页

必须展示分析步骤：

```text
读取样本
提取底层特征
生成向量表示
寻找相似性结构
生成审美报告
```

### 4.4 报告页

必须展示：

- 总体摘要
- 底层特征摘要
- 相似性分组
- 可能解释
- 重点洞察
- 证据
- 反馈按钮

反馈选项：

```text
不像我
不确定
有点像
很像我
```

## 5. V1 PostgreSQL 表

V1 只建以下业务表。

### 5.1 `users`

V1 可以只使用匿名用户。

字段：

```text
id
anonymous_id
created_at
updated_at
```

### 5.2 `aesthetic_inputs`

保存原始输入。

字段：

```text
id
user_id
type
content_text
file_url
source
title
description
created_at
updated_at
```

### 5.3 `input_features`

保存单个输入的底层特征。

字段：

```text
id
input_id
feature_type
model_name
prompt_version
feature_json
summary
created_at
```

`feature_json` 必须使用 `04-审美表征体系文档.md` 定义的结构：

```json
{
  "lowLevelFeatures": {
    "saturation": {
      "value": "low",
      "confidence": 0.82,
      "evidence": ["画面整体以低纯度灰蓝色为主"]
    }
  },
  "sampleEvidence": ["画面中大面积灰色墙面"]
}
```

### 5.4 `embedding_records`

保存 embedding metadata。向量本体写入 ChromaDB。

字段：

```text
id
owner_type
owner_id
collection_name
chroma_id
model_name
vector_dimension
created_at
```

V1 `owner_type` 只需要支持：

```text
input
```

### 5.5 `analysis_jobs`

保存分析任务状态。

字段：

```text
id
user_id
status
input_count
error_message
started_at
finished_at
created_at
```

状态枚举：

```text

queued
running
feature_extracting
embedding_generating
vector_writing
similarity_grouping
interpreting
report_generating
completed
failed
partial_failed
cancelled
```

### 5.6 `aesthetic_reports`

保存报告。

字段：

```text

job_id
title
summary

similarity_groups_json
interpretations_json
report_json

created_at
```

### 5.7 `possible_interpretations`

保存解释候选。

字段：

```text

```

`target_type` V1 支持：


### 5.8 `insights`

保存报告中的洞察。

字段：


### 5.9 `insight_feedback`

字段：

## 6. V1 ChromaDB Collection

V1 只需要一个 collection：

```text

```

metadata 必须包含：

```json
{
  "inputId": "input_001",
  "userId": "user_001",
  "jobId": "job_001",
  "inputType": "image",
  "modelName": "embedding-model-name",
  "createdAt": "2026-05-15T00:00:00Z"
}
```

## 7. V1 API

### 7.1 创建输入

```text
POST /api/inputs
```

用途：

- 上传图片。
- 提交文本。
- 返回 input id。

### 7.2 创建分析任务

```text
POST /api/analysis-jobs
```

用途：

- 接收 input ids。
- 创建 job。
- 触发分析 workflow。

### 7.3 查询分析状态

```text
GET /api/analysis-jobs/:id
```

用途：

- 返回 job status。
- 返回失败原因。
- 返回 report id，若已完成。

### 7.4 获取报告

```text
GET /api/reports/:id
```

用途：

- 返回结构化报告。
- 返回 insights。
- 返回 evidence refs。

### 7.5 提交反馈

```text
POST /api/insights/:id/feedback
```

用途：

- 保存用户对单条洞察的反馈。
- V1 不更新画像。

## 9. V1 Workflow

V1 workflow 到 `collectFeedback` 为止：

```text
createAnalysisJob
loadInputs
saveRawInputMetadata
extractLowLevelFeatures
generateEmbeddings
writeVectorsToChromaDB
groupInputsBySimilarity
generatePossibleInterpretations
generateReport
saveReportAndInsights
updateJobStatus
collectFeedback
```

V1 不执行：

```text
updateUserProfile
generateTimelineEvent
retrieveAestheticKnowledge
agentPlan
```

## 10. V1 完成标准

V1 完成需要满足：

- 用户可以提交 3-10 个图片 / 文本样本。
- 输入能保存到 PostgreSQL。
- 图片 / 文本能生成统一底层特征 JSON。
- embedding metadata 能保存，向量能写入 ChromaDB。
- 系统能生成 1-3 个相似性分组；样本不足时能跳过分组。
- 系统能生成结构化报告。
- 每条洞察至少有一个 evidence ref。
- 用户反馈能保存。
- 分析任务状态可查询。
- 基础 analysis log 能记录 step、状态、模型、耗时和错误。
- 报告不包含人格诊断、玄学表达或无证据高级词。
