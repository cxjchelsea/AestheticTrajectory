# AI 审美形成系统：输出报告模板文档

## 1. 文档目的

这份文档定义系统生成审美报告时的结构、语气、模板和禁用表达。

目标是让 AI 输出具备：

- 洞察感
- 可解释性
- 克制感
- 审美感
- 证据感
- 非玄学感

报告不应该像心理测试，也不应该像普通标签分类，而应该像一份有依据的审美观察笔记。

当前实现边界：

```text
V1 / V2-A 已实现：总体摘要、底层特征、相似性分组、可能解释、重点洞察、disclaimer 和反馈入口。
V2-B planned：报告可引用轻量画像 evidence，但画像本身尚未实现。
V2-D planned：最近两次报告对比与近期变化提示。
V3+ planned：RAG 知识证据、长期 personalized retrieval 和 Agent 生成流程。
```

## 2. 报告生成原则

### 2.1 先观察，再解释

报告必须区分：

- 系统观察到什么
- 系统基于观察做出什么推测

推荐表达：

> 系统观察到你的输入中反复出现低饱和色、空旷空间和人物缺席，因此推测你近期可能被一种“结构化孤独感”吸引。

避免表达：

> 你是一个孤独又敏感的人。

### 2.2 每条洞察都要有依据

每个结论至少需要绑定 2-3 个证据：

- 来自哪些输入
- 出现了哪些特征
- 为什么这些特征支持结论

证据来源分为三类：

- 用户输入证据：图片、文本、历史记录中的具体特征。
- 个性化历史证据：用户过去报告、反馈和长期偏好。
- 审美知识证据：通过 RAG 检索到的风格知识、标签解释或设计理论。

报告中的核心判断必须优先来自用户输入证据。RAG 知识只能增强解释，不能替代用户样本本身。

### 2.3 使用倾向性语言

审美分析不是客观诊断。系统应该使用：

- 可能
- 倾向于
- 似乎
- 系统推测
- 近期输入显示
- 在这组样本中

避免使用：

- 你就是
- 你一定
- 你的本质
- 你的灵魂
- 你命中注定

### 2.4 避免人格化诊断

系统分析的是输入，不是诊断用户。

推荐：

> 这组输入中存在明显的疏离氛围。

避免：

> 你是一个疏离的人。

## 3. 报告整体结构

MVP 报告建议包含 7 个部分：

1. 总体摘要
2. 底层特征摘要
3. 相似性分组
4. 可能解释
5. 风格矛盾
6. 重点洞察
7. 用户反馈

进阶版本可以增加：

8. 历史对比
9. 检索到的审美知识依据
10. 洞察生成链路摘要

## 4. 总体摘要模板

### 4.1 模板

```text
这组输入整体呈现出【底层特征 1】、【底层特征 2】和【底层特征 3】的倾向。

系统观察到，这些特征可能有几种解释：【解释 A】、【解释 B】。其中哪一种更贴近你，需要结合你的反馈继续判断。
```

### 4.2 示例

```text
这组输入整体呈现出低饱和、空旷空间和冷静结构的倾向。

系统观察到，这些特征可能被解释为“结构化疏离”，也可能只是你近期对“冷感空间”的偏好。哪一种更贴近你，需要通过你的反馈继续判断。
```

## 5. 底层特征模板

### 5.1 模板

```text
底层特征：【特征名称】

系统依据：
- 【证据 1】
- 【证据 2】
- 【证据 3】

解释：
这个特征说明你的这组输入中反复出现【具体可观察现象】。它本身不是最终结论，而是后续解释的依据。
```

### 5.2 示例

```text
底层特征：低饱和

系统依据：
- 多张图片以灰蓝、米白、黑色为主
- 高纯度颜色出现较少
- 文本情绪表达也偏克制

解释：
这个特征说明你的这组输入中反复出现降低视觉刺激的色彩选择。它可能支持“克制”“冷感”“旧照片感”等不同解释，但不能单独推出一个固定主题。
```

## 6. 相似性分组模板

### 6.1 模板

```text
风格组：【动态命名】

包含输入：
- 【输入 A】
- 【输入 B】
- 【输入 C】

共同特征：
- 【共同特征 1】
- 【共同特征 2】
- 【共同特征 3】

可能解释：
- 【解释 A】
- 【解释 B】

不确定性：
这些输入共同构成了一个风格中心，但它的命名不是事实，只是基于当前特征的解释候选。
```

### 6.2 示例

```text
风格组：冷感低密度组

包含输入：
- 灰色混凝土建筑图片
- 黑白街道摄影
- 关于夜晚房间的文字

共同特征：
- 冷色调
- 空旷空间
- 人物缺席
- 强结构线条

可能解释：
- 结构化疏离
- 冷感空间偏好

不确定性：
这些输入虽然共同呈现冷色、低密度和人物缺席，但这不一定代表稳定的“孤独感”，也可能只是你近期对简洁空间和冷色材质更敏感。
```

## 7. 可能解释模板

### 7.1 模板

```text
可能解释：【解释名称】

系统观察：
在这组输入中，【特征 A】、【特征 B】和【特征 C】反复出现。

解释依据：
这些特征可以被解释为【解释名称】，因为【解释逻辑】。

另一种可能：
同一组特征也可能被解释为【另一种解释】。

不确定性：
这只是基于当前样本的解释候选，不是对你长期审美或人格的确定判断。
```

### 7.2 示例

```text
可能解释：未完成的温柔

系统观察：
在这组输入中，柔软材质、低叙事片段和生活痕迹反复出现。

解释依据：
这些特征可以被解释为一种不完整但温和的日常感，因为它们没有强烈戏剧性，却反复出现生活痕迹和柔软材质。

另一种可能：
这也可能只是你近期更偏好生活化、低刺激、非摆拍的视觉内容。

不确定性：
这个解释需要通过你的反馈确认，不能直接作为稳定审美主题。
```

## 8. 风格矛盾模板

### 8.1 模板

```text
风格矛盾：【倾向 A】 vs 【倾向 B】

系统观察：
你的输入中一方面出现【A 的证据】，另一方面也出现【B 的证据】。

系统解释：
这说明你的审美并不是单向度的。你可能不是只喜欢【A】，而是在【A】和【B】之间寻找一种张力。
```

### 8.2 示例

```text
风格矛盾：秩序感 vs 衰败感

系统观察：
你的输入中一方面出现几何构图、对称结构和极简空间，另一方面也出现锈迹、裂缝和废弃建筑。

系统解释：
这说明你的审美并不是单纯追求干净与秩序。你可能更在意的是秩序被时间侵蚀之后留下的结构感。
```

## 9. 重点洞察模板

### 9.1 标准结构

```text
洞察标题：
【一句话说明洞察】

系统观察：
【描述系统从输入中看到的事实】

输入依据：
- 【证据 1】
- 【证据 2】
- 【证据 3】

可能解释：
【基于证据做出温和推测】

不确定性：
【说明这只是基于当前样本，不是对用户本人的绝对判断】
```

### 9.2 示例

```text
洞察标题：
你可能正在从叙事性审美转向结构性审美。

系统观察：
这组输入中，明确人物和情节并不多，反而有大量空间、线条、材质和构图特征。

输入依据：
- 多张图片以建筑结构和空间关系为主体
- 文本内容更像片段，而不是完整故事
- 人物存在感弱，物体和空间更突出

可能解释：
这可能说明你近期更容易被“形式如何组织”吸引，而不是被“故事讲了什么”吸引。你的审美注意力正在从叙事内容转向结构关系。

不确定性：
这只是基于本次输入的观察。如果后续输入中出现更多人物、事件和故事性内容，这个判断可能会发生变化。
```

## 10. 审美变化模板

用于第二次及之后的报告。

### 10.1 模板

```text
和上一次相比，你这次的输入在【变化维度】上发生了变化。

上一次更明显的是：
- 【旧特征 1】
- 【旧特征 2】

这一次更明显的是：
- 【新特征 1】
- 【新特征 2】

系统推测：
你的审美注意力可能正在从【旧方向】转向【新方向】。
```

### 10.2 示例

```text
和上一次相比，你这次的输入在空间感上发生了变化。

上一次更明显的是：
- 室内、近距离、柔软材质
- 暖色调和日常物件

这一次更明显的是：
- 空旷建筑
- 冷色调
- 人物缺席

系统推测：
你的审美注意力可能正在从亲密的日常感转向更冷静、更结构化的空间感。
```

## 11. 用户反馈模板

每条洞察后添加：

```text
这条洞察对你来说：
[ ] 完全不像我
[ ] 有点意思
[ ] 很像我
[ ] 有被看见的感觉
```

可选补充：

```text
你也可以补充一句：
“哪里说中了 / 哪里不准确？”
```

## 12. 禁止输出类型

### 12.1 空泛人格判断

禁止：

```text
你是一个敏感而孤独的人。
```

替代：

```text
这组输入中反复出现人物缺席、空旷空间和低声叙事，因此系统观察到一种疏离感倾向。
```

### 12.2 玄学表达

禁止：

```text
你的灵魂天生属于夜晚。
```

替代：

```text
夜晚、低明度和弱光场景在这组输入中出现频率较高，说明你近期可能更容易被暗色环境中的安静感吸引。
```

### 12.3 绝对判断

禁止：

```text
你一定讨厌热闹。
```

替代：

```text
在这组样本中，热闹、密集、人群化的场景较少，因此系统暂时没有观察到你对高密度社交场景的明显偏好。
```

### 12.4 无依据高级词

禁止：

```text
你的审美充满后现代的精神性。
```

替代：

```text
如果要使用“后现代”这类词，必须说明它来自哪些输入特征，例如拼贴、反叙事、符号混杂或结构解构。
```

## 13. 报告语气规范

推荐语气：

- 冷静
- 温和
- 有观察感
- 有解释感
- 不居高临下
- 不神秘化

推荐句式：

- “系统观察到……”
- “这组输入中反复出现……”
- “这些特征可以被解释为……”
- “另一种可能是……”
- “它可能说明……”
- “这不一定代表长期稳定偏好，但说明近期……”

避免句式：

- “你是一个……的人”
- “你内心深处……”
- “你真正渴望的是……”
- “这说明你的灵魂……”

## 15. 判断一份报告是否合格

合格报告应该满足：

- 用户能看懂
- 至少有 1 条洞察让用户觉得“说中了”
- 每个结论都有依据
- 重要解释至少提供一个替代解释
- 不像心理测试
- 不像标签堆砌
- 不过度绝对
- 有继续使用的欲望

不合格报告通常表现为：

- 很多抽象形容词
- 没有输入证据
- 把高层解释当成事实
- 所有风格都被解释成同一套文艺语言
- 谁看都适用
- 像算命
- 像普通 GPT 夸奖
- 无法用于后续长期分析
