# AI 审美形成系统：开发任务拆分与迭代计划

这份文档把版本目标拆成可执行开发任务。完整的产品版本边界见 `02-版本迭代路线图.md`。

## 1. 技术选型

推荐技术栈：

- 前端：React + TypeScript + Vite
- 后端：FastAPI + Pydantic
- 业务数据库：PostgreSQL
- 数据库可视化：Navicat / DBeaver / DataGrip
- 向量库：ChromaDB
- 文件存储：本地文件目录，后续可替换对象存储
- AI 能力：MVP 可先 mock，再接入真实 LLM / vision / embedding API
- 测试：pytest + 前端组件测试

PostgreSQL 可以使用 Navicat 可视化管理。连接时只需要配置 host、port、database、username、password。

## 2. 迭代总览

| 版本 | 目标 | 核心结果 |
| --- | --- | --- |
| V0 原型 | 验证产品感觉 | 能上传样本并看到静态/半静态报告 |
| V1 精简 MVP | 跑通真实最小闭环 | 输入、特征、embedding、相似性分组、报告、反馈 |
| V2 历史与画像 | 形成长期观察雏形 | 历史报告、轻量画像、报告对比 |
| V3 检索与评估 | 提高解释质量 | personalized retrieval、RAG、评估指标、可观测 |
| V4 高级扩展 | 走向长期个性化 AI | 多模态扩展、知识图谱、Agent、MCP |

## 3. V0：可演示原型

### 目标

用最少工程量验证用户是否喜欢“上传样本后得到审美解释报告”的体验。

### 要实现的功能

- 前端首页
- 上传页 UI
- 图片 / 文字样本预览
- 静态 mock 分析结果
- 报告页 UI
- 洞察反馈按钮 UI

### 暂不实现

- 数据库
- 真实 AI 调用
- embedding
- ChromaDB
- 历史报告

### 验收标准

- 用户能完成一次前端演示流程。
- 报告结构包含总体摘要、底层特征、相似性分组、可能解释、重点洞察。
- 输出风格不像心理测试或算命。

### 可交给 AI 的任务提示

```text
请实现 AI 审美形成系统的 V0 前端原型。使用 React + TypeScript + Vite，包含首页、上传页、分析等待页和报告页。报告数据使用 mock JSON，不接后端。UI 气质保持克制、研究感、作品集可展示。
```

## 4. V1：精简 MVP

### 目标

跑通真实最小闭环：

> 上传样本 → 保存输入 → 提取底层特征 → 生成 embedding → 相似性分组 → 生成报告 → 保存反馈。

### 要实现的功能

#### 前端

- 首页
- 上传页
- 分析等待页
- 报告页
- 洞察反馈交互

#### 后端

- FastAPI 项目结构
- PostgreSQL 连接
- ChromaDB 连接
- 文件存储
- 输入创建 API
- 分析任务创建 API
- 分析状态 API
- 报告查询 API
- 反馈提交 API

#### 数据库

PostgreSQL 至少包含：

- `users` 或匿名用户表
- `aesthetic_inputs`
- `input_features`
- `analysis_jobs`
- `aesthetic_reports`
- `insights`
- `insight_feedback`
- `analysis_logs`

ChromaDB 至少包含：

- `inputs` collection

#### AI 与分析

- 图片底层特征提取
- 文本底层特征提取
- embedding 生成
- 小样本相似性分组
- possible interpretations 生成
- 结构化报告生成
- prompt 输出 schema 校验

### 验收标准

- 真实输入能保存到 PostgreSQL。
- 图片和文字都能生成统一底层特征 JSON。
- embedding metadata 能保存，向量能写入 ChromaDB。
- 样本能被分成 1-3 个相似性组，样本不足时能跳过分组。
- 报告每条洞察都有证据。
- 用户反馈能保存。
- prompt version、model name、latency、error type 能记录基础日志。

### 可交给 AI 的任务提示

```text
请实现 V1 精简 MVP 后端。使用 FastAPI + PostgreSQL + ChromaDB，按文档 13 的目录结构放置代码。先用 mock AI client 保持 schema 稳定，跑通输入保存、分析任务、底层特征、embedding metadata、相似性分组、报告保存和反馈 API。
```

## 5. V2：历史报告与轻量画像

### 目标

让系统从“一次性报告”进入“长期观察”的雏形。

### 要实现的功能

- 历史报告列表
- 报告详情回看
- 两次报告简单对比
- 轻量用户画像
- 被认可解释记录
- 被否定解释记录
- 稳定底层特征统计
- 基础趋势提示

### 数据库新增或强化

- `user_aesthetic_profiles`
- `aesthetic_timeline_events`
- `profile_feature_weights`

### 验收标准

- 用户能看到历史报告。
- 系统能对比最近两次报告的共同点和差异。
- 用户反馈能影响轻量画像权重。
- 被否定的解释不会作为正向偏好进入画像。

### 可交给 AI 的任务提示

```text
请实现 V2 历史报告和轻量用户画像。基于已保存的 reports、insights 和 insight_feedback，生成 accepted_interpretations、rejected_interpretations 和 stable_low_level_features，并在前端提供历史报告列表和最近两次报告对比。
```

## 6. V3：检索增强与评估

### 目标

提高解释质量，让系统更像可靠的 AI 工程项目。

### 要实现的功能

- personalized retrieval：检索用户历史输入、报告和反馈
- 小型审美知识库 RAG
- prompt versioning
- prompt registry
- evidence coverage 评估
- insight feedback hit rate
- grouping stability 评估
- observability dashboard 或日志查询

### 验收标准

- 历史检索结果能进入报告生成，但不能替代当前输入证据。
- RAG 知识只用于解释增强，不作为用户偏好证据。
- 每条洞察能追踪到输入证据、prompt version、model name 和相关检索结果。
- 能输出一份基础评估报告。

### 可交给 AI 的任务提示

```text
请实现 V3 检索增强与评估模块。新增 personalized retrieval 和小型审美知识库 RAG，要求报告中的所有外部知识都标记来源，并实现 evidence coverage、feedback hit rate、grouping stability 三类基础评估指标。
```

## 7. V4：高级扩展

### 目标

把项目扩展成长期个性化 AI 系统，而不只是报告生成工具。

### 可实现功能

- 音乐输入
- 视频输入
- 外部收藏源导入
- 审美时间轴
- 审美知识图谱
- 审美观察 Agent
- MCP 外部上下文接入
- 周报 / 月报生成

### 验收标准

- 新模态仍然进入统一表征体系。
- Agent 只在有明确工具、状态和边界时引入。
- 知识图谱中的关系必须有证据来源。
- MCP 只作为外部上下文接入层，不改变系统核心解释原则。

## 8. 第一周建议

第一周只完成 V0 + V1 的骨架，不追求所有细节。

### Day 1

- 初始化前端和后端项目。
- 建立目录结构。
- 完成首页、上传页、报告页原型。

### Day 2

- 配置 PostgreSQL。
- 建立基础表结构。
- 实现输入保存 API。

### Day 3

- 实现 mock AI client。
- 定义底层特征 schema。
- 保存 input_features。

### Day 4

- 接入 embedding mock 或真实 embedding。
- 初始化 ChromaDB collection。
- 实现相似性分组。

### Day 5

- 实现报告生成。
- 实现报告查询。
- 前端展示真实报告数据。

### Day 6

- 实现洞察反馈。
- 增加基础日志。
- 调整报告语气和证据展示。

### Day 7

- 准备 demo 样本。
- 修复边界情况。
- 整理 README 和展示文案。

## 9. 每次开发的约束

- 不直接在 API route 中写业务流程。
- 不在 service 中拼接 prompt。
- 不让 LLM 原始输出直接入库。
- 不把 ChromaDB 当业务数据库。
- 不把相似性分组说成绝对聚类结论。
- 不输出人格诊断、玄学判断或无依据高级词。

## 10. 当前最推荐的下一步

从 V0 开始，但后端目录按 V1 预留。

也就是说：

- 前端先做出完整体验。
- 后端先用 mock AI client。
- PostgreSQL 表结构先定下来。
- ChromaDB 可以在 V1 中后段接入。
- 等报告体验成立，再接真实模型。
