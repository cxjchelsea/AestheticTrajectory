# AI 审美形成系统：MVP 功能需求文档

## 1. MVP 目标

第一版 MVP 的目标不是做完整的长期成长系统，而是做出一个可以在 5 分钟内理解并产生惊喜感的核心体验：

> 用户上传一组审美样本，系统即时生成一份有解释依据的审美剖析报告。

MVP 的核心价值是：

- 第一眼能看懂
- 第一次使用就有反馈
- 输出有洞察感
- 洞察有依据
- 能收集用户反馈
- 能为长期审美轨迹积累数据

## 2. MVP 产品定位

MVP 的产品形态是：

> AI 审美镜子。

它不是完整的审美成长平台，也不是推荐系统。它先解决一个问题：

> 用户给系统一组最近喜欢的东西，系统能不能说出一些“我自己隐约感觉到但说不出来”的风格结构。

长期审美轨迹可以作为后续版本逐步叠加。

## 3. MVP 核心用户路径

### 3.1 首次使用路径

1. 用户进入首页。
2. 用户看到一句清晰的产品说明。
3. 用户上传 5-10 个审美样本。
4. 系统对样本进行多模态分析。
5. 系统生成审美剖析报告。
6. 用户查看底层特征、可能解释、风格矛盾和解释依据。
7. 用户对每条洞察反馈“像不像我”。
8. 系统保存本次分析，为后续审美轨迹做准备。

### 3.2 再次使用路径

1. 用户进入个人主页。
2. 用户看到上次的审美报告摘要。
3. 用户上传新一组样本。
4. 系统生成新报告。
5. 系统对比两次输入之间的变化。
6. 用户看到初步的风格漂移提示。

## 4. MVP 输入范围

### 4.1 第一版支持输入

第一版建议只支持两类输入：

- 图片
- 文字

图片可以包括：

- 摄影
- 穿搭
- 建筑
- 室内空间
- 设计图
- 插画
- 收藏图片

文字可以包括：

- 用户喜欢的一段话
- 书摘
- 歌词
- 自己写的句子
- 对某张图的描述

### 4.2 第一版暂不支持

第一版暂不做：

- 音乐音频分析
- 视频分析
- 第三方平台同步
- 自动导入 Pinterest / 小红书 / 豆瓣
- 社交分享社区
- 复杂 Agent 工作流
- 复杂 RAG 审美知识库
- MCP 外部上下文接入
- 图数据库或完整知识图谱
- 训练自有模型

这些可以作为后续版本扩展，避免 MVP 过重。

## 5. MVP 输出范围

系统第一次报告至少包含 6 个模块。

### 5.1 底层特征摘要

输出一组相对客观的底层特征，例如：

- 低饱和
- 中低明度
- 冷色温
- 人物缺席
- 空间密度低
- 构图复杂度中等

每个特征必须附带来源依据。

### 5.2 风格聚类

系统将用户输入分成 2-4 个风格簇。

例如：

- 冷感低密度组
- 高饱和高密度组
- 柔软日常组

每个风格簇需要说明：

- 包含哪些输入
- 共同特征是什么
- 它可能对应哪些解释

### 5.3 动态解释候选

系统从跨输入的共性中生成多个可能解释，而不是固定一个主题。

例如：

> 你的输入中反复出现“人物缺席、空间密度低、冷色温”。这可能被解释为“结构化疏离”，也可能只是近期对“冷感空间”的偏好。系统需要等待你的反馈来判断哪种解释更贴近你。

### 5.4 风格矛盾

系统指出用户审美中同时存在的不同倾向。

例如：

> 你一方面偏爱秩序感和结构感，另一方面又被衰败、破损和未完成性吸引。这说明你的审美并不是单纯追求干净，而是在“秩序”和“失控”之间寻找张力。

### 5.5 审美洞察

系统生成 3-5 条更完整的解释型洞察。

每条洞察应包含：

- 底层观察
- 依据
- 可能解释
- 另一种解释
- 不确定性
- 用户可反馈项

### 5.6 用户反馈

每条洞察后提供反馈：

```text
这条洞察：
[ ] 完全不像我
[ ] 有点意思
[ ] 很像我
[ ] 有被看见的感觉
```

反馈用于后续优化用户画像和 prompt 策略。

## 6. 功能清单

### 6.1 P0 必做功能

- 首页产品说明
- 样本上传
- 图片输入
- 文字输入
- 输入预览
- AI 分析任务
- 底层特征提取
- 风格聚类结果
- 动态解释候选生成
- 可解释依据展示
- 用户反馈
- 报告保存

### 6.2 P1 重要功能

- 历史报告列表
- 两次报告对比
- 初步审美变化提示
- 用户自定义标签
- 报告导出
- 分享图片生成

### 6.3 P2 后续功能

- 音乐分析
- 视频分析
- 平台收藏导入
- 审美时间轴
- 长期审美轨迹
- 个人风格档案
- 推荐“未来可能喜欢”的内容
- 创作灵感辅助

## 7. 页面设计

### 7.1 首页

目标是让用户 10 秒内理解系统。

首页需要包含：

- 产品一句话介绍
- 示例洞察
- 上传入口
- 简短说明“上传 5-10 个你最近喜欢的内容”

首页文案方向：

> 上传你最近喜欢的图片和文字，让 AI 分析你正在形成的审美倾向。

### 7.2 上传页

上传页需要支持：

- 图片拖拽上传
- 文字输入框
- 样本数量提示
- 样本预览
- 删除样本
- 开始分析按钮

建议限制：

- 最少 5 个样本
- 最多 15 个样本
- 图片大小上限
- 单段文字长度上限

### 7.3 分析等待页

等待页不能只是 loading。

可以展示系统正在做的步骤：

```text
正在识别视觉特征
正在提取情绪倾向
正在寻找跨输入的共同主题
正在生成可解释洞察
```

这会增强系统的研究感。

### 7.4 报告页

报告页是 MVP 的核心。

建议结构：

1. 总体结论
2. 底层特征
3. 风格聚类
4. 可能解释
5. 风格矛盾
6. 重点洞察
7. 输入依据
8. 用户反馈

### 7.5 历史页

第一版可以简单保存历史报告。

历史页包含：

- 报告时间
- 输入数量
- 关键词摘要
- 进入详情按钮

## 8. 数据保存要求

MVP 至少需要保存：

- 用户 ID
- 输入样本
- 样本类型
- 样本文本内容或图片地址
- 样本基础特征
- embedding
- 分析报告
- 洞察条目
- 用户反馈
- 创建时间

即使第一版不做复杂长期轨迹，也必须保存这些数据，因为它们是后续演化分析的基础。

## 9. AI 输出要求

AI 输出必须遵守以下原则：

- 不能直接进行人格判断
- 不能使用玄学表达
- 不能只输出抽象形容词
- 每个结论都必须关联输入依据
- 可以使用“可能”“倾向于”“系统推测”等表达
- 必须区分事实观察和解释推测

推荐输出结构：

```text
洞察标题：
观察依据：
系统解释：
不确定性：
用户反馈：
```

## 10. 成功标准

MVP 是否成立，不看用户是否长期留存，而先看以下指标：

- 用户是否能顺利完成一次上传
- 用户是否愿意读完整份报告
- 用户是否觉得至少 1 条洞察“很像我”
- 用户是否愿意保存或分享报告
- 用户是否愿意再次上传
- 报告是否有明确输入依据
- 输出是否不像 AI 算命

工程层面的成功标准包括：

- 结构化特征是否能稳定保存
- 每条洞察是否能追溯到输入证据
- embedding 或相似度结果是否能解释风格聚类
- 用户反馈是否能进入后续画像更新
- prompt / model / 输出版本是否可记录
- 报告生成流程是否能拆分为可调试步骤

## 11. 7 天开发版本

### 第 1-2 天

- 搭建前端页面
- 完成上传流程
- 定义数据结构

### 第 3-4 天

- 接入图片和文字分析
- 生成少量稳定底层特征
- 保存输入与分析结果

### 第 5 天

- 生成审美报告
- 设计报告页
- 增加用户反馈

### 第 6 天

- 调整 prompt
- 增加示例数据
- 增加多样化审美样本，避免只测试个人偏好
- 优化输出质量

### 第 7 天

- 完成 demo 演示流程
- 准备项目介绍
- 记录技术亮点

## 12. MVP 边界

第一版不要试图证明 AI 真的懂人类审美。

第一版只需要证明：

> 给定一组审美输入，系统能提取稳定底层特征，发现跨输入共性，并生成多个有依据的可能解释，再通过用户反馈判断哪些解释真正成立。

这已经足够作为一个有辨识度的 AI 项目起点。

## 13. MVP 与进阶技术边界

MVP 可以称为：

> multi-step AI workflow。

它包含输入分析、特征提取、embedding、聚类、洞察生成和反馈保存，但它还不是完整 Agent。

进阶版本再加入：

- Function Calling：把图片分析、文本分析、聚类、检索、报告生成拆成工具调用。
- RAG：检索审美知识库，增强报告解释，而不是让 LLM 凭空写。
- personalized retrieval：检索用户历史审美记录，支持长期对比。
- observability：记录 prompt、模型、特征、检索结果、洞察和反馈。
- knowledge graph：表达标签、风格、情绪、主题之间的关系。
- MCP：作为未来接入 Pinterest、Spotify、Notion、小红书等外部上下文源的扩展方案。

因此第一版不需要硬上所有热门技术，但数据结构和流程要为它们预留空间。
